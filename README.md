# Living BI Dashboard for Bitrix24

**Версия: 0.2.0.** Номер хранится в [package.json](package.json) и следует Semantic Versioning. Ветка `0.x` означает активное развитие возможностей.

Встраиваемое приложение Битрикс24, которое делает две вещи. Строит собственный дашборд по данным портала и меняет его настройки по фразе пользователя. Готовит расчётные наборы данных и публикует их в нативный BI-конструктор, где аналитик собирает по ним отчёты.

Обе части работают на данных одного портала и используют платформу Вайбкод.

## Зачем здесь Вайбкод

- **Gateway** открывает приложение внутри Битрикс24 и передаёт серверу временную сессию пользователя. Ключ приложения `vibe_app_...` и токен остаются на сервере.
- **BitrixGPT** готовит черновик изменения в инфраструктуре Битрикс24. Команда и метаданные не передаются сторонним LLM-провайдерам.
- **Black Hole** размещает серверный слой рядом с платформой и даёт постоянный диск для истории версий и реестра наборов.

Сервер запрашивает только агрегаты. Карточки клиентов и сырые персональные данные в интерфейс и в контекст модели не попадают.

## Что умеет версия 0.2.0

### Собственный дашборд

- Рендер дашборда из проверяемой JSON-спеки: KPI, столбчатые, линейные, круговые, кольцевые графики и таблицы.
- Визуальная правка названия, периода, группировки, сортировки, направления графика и палитры.
- История версий с возвратом к любой сохранённой конфигурации.
- Команда для ИИ: поддерживаемое изменение превращается в diff и сохраняется новой версией после подтверждения.

### Публикация наборов данных

- Подготовка расчётного набора по фразе пользователя через BitrixGPT.
- Проверка спецификации на сервере по каталогу возможностей.
- Публикация набора в нативный BI-конструктор с планом изменений и версионированием схемы.
- Управление опубликованным набором: проверка синхронизации и принудительный пересчёт данных.

## Как устроена работа с данными

Приложение получает из портала агрегаты: количество сделок, группы по стадиям или менеджерам, суммы и средние значения.

Блок «Данные портала» слева служит каталогом доступных сущностей. Клик по «Задачи», «Компании» или «Активности» показывает примеры тестовых записей и помечает выбранный источник. Текущий отчёт при этом сохраняется: в версии 0.2.0 основной дашборд строится по сделкам.

Кнопка «Обновить показатели» заново запрашивает агрегаты портала и обходит пятиминутный кэш.

## Публикация наборов данных

Приложение состоит из двух сервисов. Интерфейс работает внутри портала через Gateway. Adapter-сервис отвечает BI-конструктору на четыре callback-маршрута и считает строки по живой CRM.

Полный путь выглядит так.

1. Пользователь описывает нужные показатели обычной фразой, например «конверсия по менеджерам за текущий месяц».
2. BitrixGPT выбирает ключи из каталога возможностей, а сервер собирает из них спецификацию и перепроверяет её.
3. Приложение показывает preview: имя набора, поля с типами, период, фильтры и формулу расчёта.
4. После подтверждения приложение сравнивает схему с Битрикс24 и показывает план публикации.
5. Публикация создаёт коннектор, источник и датасет с префиксом `vibecode_ai_`.
6. Аналитик открывает таблицу в «Рабочем месте аналитика» и собирает по ней график.

Добавление поля к существующему набору выполняется как совместимое изменение. Для изменения типа поля приложение создаёт новую версию с суффиксом `_v2` и оставляет исходный набор нетронутым.

Чтобы уже собранный график показал свежие цифры, откройте таблицу в BI-конструкторе и нажмите «Синхронизировать с источником».

Убрать опубликованный набор можно там же: сначала удалите датасет, затем связанную с ним таблицу.

## Каталог возможностей и как его расширить

Каталог — единственный источник правды о том, что умеет публикатор. Он лежит в [lib/dataset-capabilities.js](lib/dataset-capabilities.js) и описывает измерения, метрики и периоды.

Каждая запись содержит и объявление, и поведение. Измерение знает, какие поля датасета оно даёт и как разложить по ним сделку. Метрика знает код поля, тип, человеческую формулу и функцию расчёта. Период знает, как посчитать свои границы.

Из каталога строятся системный промпт для BitrixGPT, схема инструмента и весь расчёт в движке. Поэтому **новая метрика добавляется правкой одного файла**.

Версия 0.2.0 поддерживает сущность `crm.deal`, измерения «неделя», «менеджер» и «воронка», метрики «всего сделок», «выигранные сделки» и «конверсия», периоды «текущий месяц», «квартал» и «год».

Модель выбирает ключи только из каталога. Имена полей, типы, параметры REST-вызовов и правила расчёта формирует сервер. Когда запрос выходит за каталог, приложение возвращает структурированную заявку с описанием недостающей возможности.

Тест `test/dataset-capabilities.test.js` следит за тем, чтобы списки не разъехались: он сверяет схему инструмента и промпт с ключами каталога.

## Как менять дашборд

### Визуальный редактор

Название отчёта и графика, сортировка стадий, группировка, ориентация, палитра и период данных. После правки нажмите «Сохранить версию».

### Команда для ИИ

Опишите изменение обычной фразой, например «сделай график по менеджерам горизонтальным и в цветах бренда». Приложение покажет diff и применит его после подтверждения.

Когда запрос требует новой функции, приложение формирует структурированную заявку для агента разработки: чего не хватает, что нужно сделать и как проверить результат.

## Быстрый старт

Требования: Node.js 20+, npm и ключ Вайбкода для вашего портала.

```bash
git clone https://github.com/igorrosliakov-bitrix24/living-bi-dashboard.git
cd living-bi-dashboard
cp .env.example .env
# Добавьте VIBECODE_API_KEY в .env
npm ci
npm run check
npm run seed
npm run dev
```

Откройте `http://127.0.0.1:5174`. Для локального режима достаточно личного ключа `vibe_api_...`, ключ приложения нужен для встройки в портал. После изменения `.env` перезапустите `npm run dev`.

### Тестовые данные

`npm run seed` создаёт небольшой набор с префиксом `VIBECODE_DEMO_BI`.

Для проверки скорости рендера подойдёт нагрузочный набор:

```bash
npm run seed:load -- --deals=2000 --confirm
```

Для демонстрации публикатора нужен набор новых сделок, распределённый по неделям и менеджерам:

```bash
npm run seed:intake -- --deals=360 --weeks=8 --manager-ids=30,32,34,36,38 --confirm
```

Каждый скрипт требует явного подтверждения и останавливается при повторном запуске. Режим `--resume` продолжает прерванный прогон, `--spread` перераспределяет даты уже созданного набора.

## Развёртывание

Полная инструкция: [docs/SETUP.md](docs/SETUP.md), настройка публикации: [docs/BI_DATASET_DEPLOYMENT.md](docs/BI_DATASET_DEPLOYMENT.md).

Проект разворачивается на два отдельных сервера.

**Интерфейс** работает с политикой доступа `OWNER_ONLY` и открывается через placement Битрикс24. Ему нужны `VIBE_APP_KEY`, `BI_CONNECTOR_BASE_URL`, `ADAPTER_CONTROL_KEY` и постоянный путь `DASHBOARD_STATE_PATH`.

**Adapter-сервис** работает с политикой `PUBLIC`, потому что Битрикс24 обращается к нему сервер-к-серверу. Ему нужны OAuth-пара локального приложения, `OAUTH_STATE_ENCRYPTION_KEY`, `BITRIX24_INSTALL_SECRET` и тот же `ADAPTER_CONTROL_KEY`.

Оба сервера создавайте с явным `placement: "dedicated"` и постоянным диском для состояния. Каталог приложения очищается при каждой выкладке, поэтому реестр наборов и OAuth-состояние храните в отдельном каталоге данных.

Для работы с датасетами нужно локальное приложение Битрикс24 со scope `crm`, `biconnector` и `user_brief`, в режиме «Использует только API».
