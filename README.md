# Living BI Dashboard for Bitrix24

Встраиваемый дашборд Битрикс24, который помогает визуально менять настройки отчёта и готовить безопасные предложения через BitrixGPT. Это отдельное приложение рядом с нативным BI-конструктором: оно использует данные того же портала, но не читает и не редактирует нативные BI-отчёты, потому что для этого нет доступного REST API.

## Зачем здесь Вайбкод

- **Gateway** открывает приложение внутри Битрикс24 и передаёт серверу временную сессию пользователя. Ключ приложения `vibe_app_...` и токен не попадают в JavaScript страницы.
- **BitrixGPT** готовит черновик изменения в инфраструктуре Битрикс24. Команда и метаданные дашборда не передаются сторонним LLM-провайдерам.
- **Galaxy** размещает BFF (серверный слой между интерфейсом и API) рядом с платформой и даёт постоянный том `/data` для истории версий.
- Сервер запрашивает только агрегаты; карточки клиентов и сырые персональные данные в интерфейс и контекст ИИ не передаются.

## Возможности текущего MVP

- дашборд из проверяемой JSON-спеки;
- данные сделок, компаний, задач и активностей через API Вайбкода;
- KPI, столбчатые, линейные, круговые, кольцевые графики и таблицы;
- визуальная правка названия, периода, группировки, сортировки, направления и палитры;
- вычисляемые KPI вида `один KPI / другой KPI` без выполнения произвольного кода;
- черновик изменения через BitrixGPT с серверной валидацией и подтверждением пользователя;
- история версий и выбор предыдущей версии без создания дубликата;
- доступ из левого меню Битрикс24 через Gateway.

## Ограничения

- Это не редактор нативного BI-конструктора и не замена полноценного BI для сложных срезов.
- Агрегации Вайбкода работают по выборке до 5000 записей; интерфейс должен показывать ограничение выборки.
- В MVP нет записи в CRM или задачи: ИИ меняет только настройки дашборда.

## Быстрый старт

Требования: Node.js 20+, npm и ключ Вайбкода для вашего портала.

```bash
git clone https://github.com/igorrosliakov-bitrix24/living-bi-dashboard.git
cd living-bi-dashboard
cp .env.example .env
# Добавьте VIBECODE_API_KEY в .env
npm ci
npm run check
npm run seed
npm run dev
```

Откройте `http://127.0.0.1:5174`. Для локального режима достаточно личного `vibe_api_...`; ключ приложения нужен для встройки в портал.

### Нагрузочный набор для демонстрации

Для проверки скорости рендера на 1–2 тыс. сделок используйте отдельный набор `VIBECODE_LOAD_BI`. Команда требует явного подтверждения и останавливается, если такой набор уже есть на портале:

```bash
npm run seed:load -- --deals=2000 --confirm
```

Скрипт создаёт 3 тестовые компании и указанное число сделок, распределяет их по стадиям и датам за последние 6–12 месяцев. По умолчанию записи назначаются владельцу портала. Для портала с несколькими сотрудниками можно распределить сделки по известным идентификаторам: `--manager-ids=1,4,9`.

## Свой портал и production

Полная инструкция: [docs/SETUP.md](docs/SETUP.md). Она охватывает создание ключей, запуск тестовых данных, Galaxy-деплой, настройку `appUrl` и placement в меню Битрикс24.

Для production требуются Node 20, `npm ci --omit=dev`, `npm run start`, порт `3000`, `NODE_ENV=production`, `VIBE_APP_KEY` и постоянный путь `DASHBOARD_STATE_PATH=/data/living-bi-dashboard/dashboard-state.json`.

## Проверки

```bash
npm run lint
npm test
npm run audit
```

Тесты проверяют валидацию спеки, получение агрегатов, безопасные вычисляемые KPI, историю версий, Gateway, seed-план и защиту входных данных. Сценарий демонстрации для статьи: [docs/demo-script.md](docs/demo-script.md).

GitHub Actions запускает `npm run check` и `npm run audit` при каждом push и pull request.
