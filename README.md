# Living BI Dashboard for Bitrix24

**Версия: 0.1.0 (первый MVP-релиз).** Версия хранится в [package.json](package.json) и следует формату Semantic Versioning: пока проект развивается, номер `0.x` означает MVP с меняющимися возможностями.

Встраиваемый дашборд Битрикс24 для настройки отчётов и подготовки безопасных предложений через BitrixGPT. Приложение работает рядом с нативным BI-конструктором и использует данные того же портала. В текущей версии оно строит собственные дашборды: REST API для чтения и редактирования конфигураций нативных BI-отчётов пока недоступен.

## Зачем здесь Вайбкод

- **Gateway** открывает приложение внутри Битрикс24 и передаёт серверу временную сессию пользователя. Ключ приложения `vibe_app_...` и токен не попадают в JavaScript страницы.
- **BitrixGPT** готовит черновик изменения в инфраструктуре Битрикс24. Команда и метаданные дашборда не передаются сторонним LLM-провайдерам.
- **Galaxy** размещает BFF (серверный слой между интерфейсом и API) рядом с платформой и даёт постоянный том `/data` для истории версий.
- Сервер запрашивает только агрегаты; карточки клиентов и сырые персональные данные в интерфейс и контекст ИИ не передаются.

## Что умеет версия 0.1.0

- дашборд из проверяемой JSON-спеки;
- данные сделок, компаний, задач и активностей через API Вайбкода;
- KPI, столбчатые, линейные, круговые, кольцевые графики и таблицы;
- визуальная правка названия, периода, группировки, сортировки, направления и палитры;
- готовый сценарий конверсии новых клиентов: квартальный период, исключение воронки по названию и вычисляемый KPI;
- вычисляемые KPI вида `один KPI / другой KPI` без выполнения произвольного кода;
- команда для ИИ: поддерживаемые изменения превращаются в diff, после подтверждения сохраняются новой версией;
- структурированная заявка для агента разработки, когда запрос требует новой функции;
- история версий и выбор предыдущей версии без создания дубликата;
- доступ из левого меню Битрикс24 через Gateway;
- 5-минутный кэш агрегатов и принудительное обновление показателей.

## Как устроена работа с данными

Приложение получает из портала агрегаты: количество сделок, группы по стадиям или менеджерам, суммы и средние значения. Карточки CRM в браузер и в контекст ИИ не загружаются.

Блок «Данные портала» слева служит каталогом доступных сущностей. Клик по «Задачи», «Компании» или «Активности» показывает примеры тестовых записей и помечает выбранный источник. Текущий отчёт от этого действия не меняется: в 0.1.0 ещё нет кнопки «Добавить виджет из этой сущности». Поэтому после выбора «Задачи» график сделок остаётся графиком сделок.

Кнопка «Обновить показатели» заново запрашивает агрегаты портала и обходит 5-минутный кэш. Она не сохраняет настройки, не создаёт данные CRM и не добавляет новые виджеты.

## Как менять дашборд

### Визуальный редактор

Измените название, сортировку, группировку, ориентацию, палитру или период и нажмите «Сохранить версию». До сохранения появляется отметка о несохранённых изменениях. Каждое сохранение создаёт следующую версию настроек; кнопка «Вернуться к версии N» выбирает существующий снимок и не размножает историю.

«Новый дашборд» возвращает приложение к стартовой конфигурации и очищает историю его версий. Данные CRM, компании, сделки и задачи на портале остаются без изменений. В 0.1.0 это сброс текущего дашборда, а не создание набора нескольких независимых дашбордов.

### Команда для ИИ

1. Введите фразу в поле «Команда для ИИ».
2. Нажмите «Подготовить изменение».
3. Прочитайте diff: приложение пока ничего не меняет.
4. Нажмите «Применить предложение».
5. При необходимости нажмите «Обновить показатели» и вернитесь к прошлой версии через историю.

Поддерживаемая фраза для демонстрации:

```text
Сделай график по менеджерам горизонтальным и в цветах бренда, KPI-карточки подними наверх.
```

Результат этой команды в 0.1.0:

- график группируется по `assignedById`, поэтому вместо стадий видны менеджеры;
- bar-график становится горизонтальным;
- применяется палитра Bitrix24: голубой, синий, зелёный, оранжевый и розовый;
- KPI-карточки остаются над графиками. Это закреплённый порядок интерфейса, поэтому отдельного визуального перемещения может быть не видно, если карточки уже находятся сверху.

Для этого стабильного визуального сценария используется безопасный обработчик поддерживаемых настроек. BitrixGPT подключается для более сложного анализа и формирования заявок на развитие; модель не создаёт код приложения прямо во время работы пользователя.

Поддерживаемый логический сценарий:

```text
Конверсию считай только по новым клиентам, исключи воронку «Тест», период — текущий квартал.
```

Он добавляет KPI общего числа новых клиентов, успешных сделок и конверсии, применяет `isReturning: false`, период текущего квартала и исключение воронки по названию. Название «Тест» сопоставляется со справочником воронок при запросе данных. Если такой воронки в портале пока нет, приложение показывает предупреждение, а правило автоматически начнёт работать после её появления.

## Когда появляется заявка для разработки

Запросы за пределами текущей конфигурации показывают блок «Нужна доработка». BitrixGPT формирует копируемую заявку: недостающие возможности, ожидаемую работу и критерии готовности. Например:

```text
Добавь виджет: просроченные задачи по отделам и динамика просрочки по неделям.
```

В 0.1.0 такая команда не добавляет виджет автоматически. Для результата нужны новые возможности: данные об отделах, недельная агрегация и отдельный тип виджета. Заявку можно скопировать и передать разработчику или внешнему агенту разработки.

## Честные ограничения версии 0.1.0

| Область | Текущее поведение |
|---|---|
| Нативный BI-конструктор | Приложение не изменяет нативные BI-отчёты Битрикс24. Оно хранит и редактирует конфигурации собственного дашборда. |
| Сущности слева | «Компании», «Активности» и «Задачи» открывают каталог и примеры данных. Создание виджета из выбранной сущности ещё не реализовано. |
| ИИ-команды | Поддерживаются конкретные безопасные настройки и сценарий конверсии. Более широкий запрос заканчивается заявкой для разработки. |
| KPI-карточки | Карточки всегда расположены выше графиков; свободная перестановка блоков и drag-and-drop отсутствуют. |
| Палитры | В интерфейсе доступна палитра Bitrix24. Пользовательские бренд-цвета и редактор палитр пока отсутствуют. |
| Несколько дашбордов | Кнопка «Новый дашборд» сбрасывает текущую конфигурацию. Каталог нескольких сохранённых дашбордов пока отсутствует. |
| Данные | Вайбкод агрегирует до 5000 записей на числовую агрегацию. При ограниченной выборке интерфейс показывает соответствующее сообщение. |
| Запись в CRM | Приложение не создаёт, не обновляет и не удаляет сделки, компании, задачи или другие записи CRM. |
| Доступ | Работа внутри портала требует открытия через placement Битрикс24: Gateway передаёт пользовательскую сессию серверу. Прямой URL Galaxy для запросов к данным не подходит. |

Ограничения и статус ближайших задач поддерживаются в [docs/PROGRESS.md](docs/PROGRESS.md). Сценарии для статьи собраны в [docs/demo-script.md](docs/demo-script.md).

## Быстрый старт

Требования: Node.js 20+, npm и ключ Вайбкода для вашего портала.

```bash
git clone https://github.com/igorrosliakov-bitrix24/living-bi-dashboard.git
cd living-bi-dashboard
cp .env.example .env
# Добавьте VIBECODE_API_KEY в .env
npm ci
npm run check
npm run seed
npm run dev
```

Откройте `http://127.0.0.1:5174`. Для локального режима достаточно личного `vibe_api_...`; ключ приложения нужен для встройки в портал. После изменения `.env` перезапустите `npm run dev`.

### Нагрузочный набор для демонстрации

Для проверки скорости рендера на 1–2 тыс. сделок используйте отдельный набор `VIBECODE_LOAD_BI`. Команда требует явного подтверждения и останавливается, если такой набор уже есть на портале:

```bash
npm run seed:load -- --deals=2000 --confirm
```

Скрипт создаёт 3 тестовые компании и указанное число сделок, распределяет их по стадиям и датам за последние 6–12 месяцев. По умолчанию записи назначаются владельцу портала. Для портала с несколькими сотрудниками можно распределить сделки по известным идентификаторам: `--manager-ids=1,4,9`.

Для заранее заданных, наглядно неравномерных долей используйте `--manager-distribution=id:количество,...`. Сумма количеств должна совпадать с `--deals`:

```bash
npm run seed:load -- --deals=2000 --manager-distribution=30:700,32:450,34:350,36:300,38:200 --confirm
```

Если выполнение было прервано, повторите ту же команду с `--resume`. Скрипт сверит уже созданные записи и продолжит с недостающих.

## Свой портал и production

Полная инструкция: [docs/SETUP.md](docs/SETUP.md). Она охватывает создание ключей, запуск тестовых данных, Galaxy-деплой, настройку `appUrl` и placement в меню Битрикс24. После каждого деплоя обновляйте страницу приложения, открытого через левое меню портала.

Для production требуются Node 20, `npm ci --omit=dev`, `npm run start`, порт `3000`, `NODE_ENV=production`, `VIBE_APP_KEY` и постоянный путь `DASHBOARD_STATE_PATH=/data/living-bi-dashboard/dashboard-state.json`.

## Проверки

```bash
npm run lint
npm test
npm run audit
```

Тесты проверяют валидацию спеки, получение агрегатов, безопасные вычисляемые KPI, историю версий, Gateway, seed-план и защиту входных данных. Сценарий демонстрации для статьи: [docs/demo-script.md](docs/demo-script.md).

GitHub Actions запускает `npm run check` и `npm run audit` при каждом push и pull request.
