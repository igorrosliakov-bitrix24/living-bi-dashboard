# Preview первого расчётного датасета

**Дата проверки:** 19.08.2026  
**Портал:** `chepyuk.bitrix24.ru`  
**Режим:** только чтение

## Что проверено

OAuth-приложение ID `1435` прочитало только метаданные и технические поля CRM. Записи, отчёты, приложения и датасеты портала не изменялись.

У сделок доступны все базовые поля для расчёта: ответственный, дата создания, воронка, стадия, сумма и признак повторной сделки. Всего API вернул 1 074 поля сделок, включая 1 016 пользовательских. На портале настроено 27 воронок и 86 активных пользователей.

За период с 1 июля по 19 августа 2026 года найдено 568 сделок. После исключения повторных сделок и 11 воронок, названия которых содержат `test` или `тест`, для расчёта осталось 459 сделок у 9 менеджеров.

## Почему первым не берём датасет конверсии

Среди 568 сделок квартала только одна имеет успешную семантику стадии. Поэтому конверсия по менеджерам и неделям почти везде будет равна нулю. Технически такой расчёт возможен, но он плохо показывает пользу продукта на текущих данных.

Для первого эксперимента выбран показатель входящего потока сделок. Он использует те же безопасные фильтры и даёт наглядный результат уже сейчас.

## Предлагаемый датасет

**Имя:** `vibecode_ai_deal_intake_weekly`

**Назначение:** показать, сколько новых сделок поступает каждому менеджеру по неделям, какова их сумма и доля менеджера в общем недельном потоке.

**Источники:** сделки CRM и краткий справочник пользователей. Содержимое карточек, комментарии и контакты клиентов в набор не входят.

**Фильтры:**

1. Период определяется по `DATE_CREATE` и ограничивается текущим кварталом.
2. Используются сделки с `IS_RETURN_CUSTOMER = N`.
3. Исключаются выбранные тестовые воронки по их числовым `CATEGORY_ID`.

## Схема

| Поле | Тип BI | Смысл |
|---|---|---|
| `WEEK_START` | дата | Понедельник соответствующей недели |
| `MANAGER_ID` | целое число | ID ответственного сотрудника |
| `MANAGER_NAME` | строка | Имя ответственного сотрудника |
| `CURRENCY_ID` | строка | Валюта суммы; разные валюты не складываются |
| `NEW_DEALS` | целое число | Число новых сделок за неделю |
| `PIPELINE_AMOUNT` | дробное число | Сумма новых сделок |
| `AVERAGE_AMOUNT` | дробное число | Средняя сумма сделки |
| `WEEKLY_SHARE_PERCENT` | дробное число | Доля менеджера в недельном потоке, % |

## Обезличенный пример результата

| Неделя | Менеджер | Новые сделки | Сумма | Средняя сумма | Доля недели |
|---|---|---:|---:|---:|---:|
| 17.08.2026 | Менеджер A | 15 | 11 020 | 734,67 | 88,24% |
| 17.08.2026 | Менеджер B | 2 | 2 000 | 1 000 | 11,76% |
| 10.08.2026 | Менеджер A | 56 | 48 060 | 858,21 | 78,87% |

При предварительной проверке датасет содержал 32 строки: по одной строке на сочетание недели, менеджера и валюты.

## Что аналитик сможет собрать руками

В нативном BI-конструкторе на этом датасете можно один раз создать столбчатый график количества новых сделок по менеджерам. Вторым графиком можно показать недельную динамику суммы или доли менеджеров. После этого adapter будет пересчитывать строки, а сохранённые графики продолжат использовать тот же датасет.

## Текущий статус

Пользователь подтвердил имя, поля, фильтры и создание изолированных объектов `vibecode_ai_*`. Расчёт реализован в `lib/deal-intake-dataset.js`, adapter умеет отдавать его через callback, добавлены локальный preview и тесты формул.

Живая публикация ожидает обновления OAuth-доступа. Для автоматического refresh-flow нужно добавить `BITRIX24_OAUTH_CLIENT_ID` и `BITRIX24_OAUTH_CLIENT_SECRET` в локальный `.env`. После этого выполняются `npm run bi:preview-intake` и `npm run bi:publish-intake -- --confirm`.
