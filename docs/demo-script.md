# Сценарий демо

Этот сценарий нужен для статьи и финальной проверки MVP. Он показывает отдельный дашборд приложения: нативные BI-отчёты Битрикс24 в этом MVP не читаются и не изменяются.

## Перед началом

1. Откройте тестовый портал Битрикс24.
2. В левом меню выберите «AI-редактор BI-отчётов».
3. В блоке «Подключение и возможности» нажмите «Обновить диагностику».
4. Убедитесь, что показано «Подключено», портал и AI Router доступны.

## Сценарий 1. Визуальная настройка

1. В разделе «Настройки отчёта» измените название графика.
2. Измените сортировку стадий.
3. Нажмите «Сохранить версию».

Ожидаемый результат: график перестраивается, а в истории появляется новая версия.

## Сценарий 2. Изменение фразой

1. В поле «Команда для ИИ» введите: «Отсортируй стадии сделок по возрастанию».
2. Нажмите «Подготовить изменение».
3. Прочитайте черновик и список изменений.
4. Нажмите «Применить предложение».

Ожидаемый результат: BitrixGPT возвращает проверяемый черновик; после подтверждения появляется новая версия отчёта. Модель меняет только JSON-настройки дашборда и не получает инструментов записи в CRM.

## Сценарий 3. История и откат

1. В блоке «Версии отчёта» выберите предыдущую версию.
2. Нажмите кнопку отката, если она доступна для версии.

Ожидаемый результат: приложение создаёт новую актуальную версию с прежними настройками. История не перезаписывается.

## Формулировка для статьи

Приложение строит отдельный дашборд рядом с нативным BI-конструктором и работает с данными того же портала. В MVP нет API для чтения или редактирования нативных BI-отчётов. Команда пользователя и метаданные дашборда обрабатываются BitrixGPT в инфраструктуре Битрикс24; данные не передаются сторонним LLM-провайдерам.
