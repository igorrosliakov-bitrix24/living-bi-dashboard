# Сценарий демо

Этот сценарий показывает отдельный дашборд приложения. Он использует данные того же портала, что и нативный BI-конструктор. REST API Битрикс24 позволяет управлять датасетами BI-конструктора. Настройки готовых нативных BI-отчётов в MVP не читаются и не изменяются: API для их графиков, фильтров и раскладки мы ещё не подтвердили.

## Перед началом

1. Выполните `npm run seed` или подготовьте собственные сделки, компании и задачи на портале.
2. Откройте пункт «AI-редактор BI-отчётов» в левом меню Битрикс24.
3. Нажмите «Обновить показатели». Кнопка заново запрашивает агрегаты портала и обходит пятиминутный кэш.

## Сценарий 1. Визуальная настройка

1. В разделе «Настройки отчёта» выберите группировку `assignedById`.
2. Выберите горизонтальное направление и палитру `bitrix24`.
3. Нажмите «Сохранить версию».

Ожидаемый результат: KPI остаются сверху, график строится по менеджерам горизонтально, в истории появляется следующая версия.

## Сценарий 2. Изменение фразой

1. В поле «Команда для ИИ» введите: `Сделай график по менеджерам горизонтальным и в цветах бренда, KPI-карточки подними наверх`.
2. Нажмите «Подготовить изменение».
3. Проверьте черновик и список изменений.
4. Нажмите «Применить предложение».

Ожидаемый результат: BitrixGPT готовит JSON Patch, сервер проверяет доступные поля и агрегат, пользователь подтверждает изменение. В CRM при этом не создаются и не редактируются записи.

## Сценарий 3. Версии и откат

1. В блоке «Версии отчёта» выберите раннюю версию.
2. Нажмите «Вернуться к версии N».

Ожидаемый результат: выбранная существующая версия становится текущей. История остаётся прежней и новая запись не создаётся. Для совершенно нового дашборда используйте кнопку «Начать новый дашборд»: она очищает только историю настроек приложения и не меняет данные CRM.

## Сценарий 4. Конверсия новых клиентов

1. В поле «Команда для ИИ» введите: `Конверсию считай только по новым клиентам, исключи воронку «Тест», период — текущий квартал`.
2. Нажмите «Подготовить изменение».
3. Проверьте diff: период «текущий квартал», фильтры графика, KPI «Новые клиенты в воронках», «Успешные сделки новых клиентов» и «Конверсия новых клиентов».
4. Нажмите «Применить предложение», затем «Обновить показатели».

Ожидаемый результат: сервер строит агрегаты сделок с `isReturning: false`, считает успешные сделки через `stageSemanticId: "S"` и вычисляет конверсию как отношение успешных сделок к общему числу новых клиентов. Правило исключения по названию «Тест» сопоставляется со справочником воронок при каждом обновлении данных. В текущем тестовом портале такой воронки пока нет, поэтому интерфейс выводит предупреждение; после появления воронки правило начнёт применять её ID автоматически.

## Сценарий 5. Запрос, для которого нужна доработка

1. В поле «Команда для ИИ» введите: `Добавь виджет: просроченные задачи по отделам и динамика просрочки по неделям`.
2. Нажмите «Подготовить изменение».
3. Откройте блок «Заявка для агента разработки».
4. Нажмите «Скопировать заявку» и передайте текст разработчику или агенту разработки.

Ожидаемый результат: BitrixGPT определяет, какие возможности дашборда требуются для этого сценария, и формирует заявку с ожидаемым поведением и критериями готовности. Приложение не создаёт задачу во внешней системе и не меняет CRM.

## Вычисляемый KPI

В JSON-спеке можно добавить KPI с ограниченной формулой, например `won-deals / all-deals` и форматом `percent`. Сервер принимает только деление двух существующих KPI. JavaScript, SQL, вызовы API и произвольные выражения валидатор отклоняет.

## Сценарий 6. Публикация датасета в нативный BI-конструктор

Этот сценарий показывает отдельную возможность проекта. AI-редактор продолжает работать со своим дашбордом, а BI-коннектор публикует таблицу для штатного BI-конструктора Битрикс24.

1. Создайте коннектор, источник и датасет командой `npm run bi:connector-demo -- --confirm` в окружении с OAuth-токеном и постоянным публичным HTTPS callback.
2. В «Рабочем месте аналитика» откройте созданный датасет и добавьте все поля в режим «Сырые записи».
3. Сохраните таблицу как виджет нативного дашборда.

Первый кадр показывает, что BI-конструктор получил строки от adapter.

![Редактор нативного графика показывает строки из опубликованного датасета](images/native-bi-raw-records.png)

Подпись для статьи: «Нативный BI-конструктор Битрикс24 получает строки из датасета, опубликованного нашим приложением. На скриншоте видны три демонстрационные сделки, которые adapter передал через BI-коннектор».

Второй кадр показывает результат размещения таблицы на нативном дашборде.

![Таблица опубликованного датасета на нативном дашборде](images/native-bi-dashboard-table.png)

Подпись для статьи: «Таблица из опубликованного датасета размещена на нативном дашборде BI-конструктора. Битрикс24 получил три строки через BI-коннектор и показал их как виджет отчёта».

## Формулировка для статьи

Приложение строит отдельный дашборд рядом с нативным BI-конструктором и работает с данными того же портала. Команда пользователя и метаданные дашборда обрабатываются BitrixGPT в инфраструктуре Битрикс24 и Вайбкода; данные не передаются сторонним LLM-провайдерам.
