# Что строить дальше: ИИ готовит наборы данных для нативного BI Битрикс24

> Рабочий черновик второй статьи. Текст можно читать по разделам, задавать вопросы прямо по формулировкам и дорабатывать по ходу. Места для иллюстраций отмечены отдельными блоками.

## О чём эта статья

В первой статье мы исследовали границу возможностей API нативного BI Битрикс24. Проверка показала важную вещь: приложение может создавать и наполнять наборы данных для BI-конструктора, но не получает доступ к настройкам уже собранного графика.

Из этого ограничения выросла практическая идея для следующего шага. ИИ может подготовить данные для будущего отчёта: понять задачу пользователя, предложить схему таблицы, проверить её по правилам и опубликовать в BI. Аналитик затем один раз собирает график штатными средствами Битрикс24.

Так появляется понятное разделение работы. ИИ помогает с подготовкой расчётного набора. Человек выбирает форму представления и проверяет, что график действительно отвечает на бизнес-вопрос.

> **Место для скриншота 1.** Нативный BI-конструктор Битрикс24 с открытой таблицей или списком BI-таблиц.
>
> Подпись: «Нативный BI-конструктор хранит и отображает таблицы данных, из которых аналитик собирает графики».

## Две части одной аналитической задачи

Когда руководитель просит отчёт, аналитик обычно выполняет две разные работы.

Сначала он готовит данные. Нужно понять, какие сущности взять из CRM, какие записи исключить, как сгруппировать результат и какие показатели посчитать. Например, фраза «новые сделки по менеджерам за квартал» требует договориться, что считать новой сделкой, как определять менеджера и учитывать ли тестовую воронку.

Затем аналитик оформляет результат. Он выбирает таблицу, столбчатый или линейный график, назначает оси, фильтры, подписи и место виджета на дашборде.

Эти части связаны, но API Битрикс24 открывает их по-разному. Через API можно управлять наборами данных. Настройки нативного графика API сейчас не отдаёт в форме, пригодной для безопасного редактирования.

**API** — это программный интерфейс. Через него одно приложение обращается к другому по заранее описанным правилам. В нашем случае приложение отправляет запросы Битрикс24 и получает ответ в структурированном виде.

## Что именно можно автоматизировать

**Датасет**, или набор данных, — это таблица с заранее определёнными колонками. BI-конструктор читает эту таблицу и строит на её основе графики.

Для первого проверенного сценария мы подготовили набор `vibecode_ai_deal_intake_weekly`. Он содержит результаты по неделям, менеджерам и валютам:

| Колонка | Что означает |
|---|---|
| `WEEK_START` | Дата начала недели. |
| `MANAGER_ID` и `MANAGER_NAME` | Идентификатор и имя менеджера. |
| `CURRENCY_ID` | Валюта сделки. |
| `NEW_DEALS` | Число новых сделок. |
| `PIPELINE_AMOUNT` | Сумма сделок. |
| `AVERAGE_AMOUNT` | Средняя сумма сделки. |
| `WEEKLY_SHARE_PERCENT` | Доля недельного потока в процентах. |

Расчёт учитывает текущий квартал, исключает повторные сделки и воронки с названием «Тест».

Встроенные наборы Битрикс24 уже содержат исходные сделки, лиды и звонки. Перепубликовывать их без преобразования смысла мало. Пользу дают расчётные показатели: конверсия по менеджерам, когорты клиентов, скорость прохождения стадий. Ещё один полезный класс задач — данные из 1С, ERP и других систем или таблицы, которые объединяют внешние данные с CRM.

> **Место для скриншота 2.** Экран с колонками опубликованной таблицы `vibecode_ai_deal_intake_weekly`.
>
> Подпись: «В BI передаются готовые расчётные строки и заранее описанные типы колонок».

## Как выглядит сценарий для пользователя

Пользователь открывает наше приложение и пишет задачу обычными словами:

> Нужны новые сделки CRM по менеджерам, неделям и валютам за текущий квартал, без повторных сделок и без воронки «Тест».

Дальше приложение проходит несколько шагов.

1. BitrixGPT получает запрос и предлагает рецепт датасета.
2. Сервер проверяет рецепт по разрешённому шаблону.
3. Интерфейс показывает preview: название, период, фильтры, формулу и список полей.
4. Пользователь подтверждает черновик, затем отдельно подтверждает публикацию.
5. Битрикс24 создаёт или находит датасет.
6. Аналитик открывает его в нативном BI-конструкторе и один раз собирает нужный график.

**Preview** — предварительный просмотр. Он показывает будущий результат до внешнего действия. На этом шаге пользователь может увидеть неподходящий фильтр или колонку и остановиться до публикации.

> **Место для скриншота 3.** Блок AI Dataset Publisher в нашем приложении: запрос пользователя и preview схемы.
>
> Подпись: «Перед публикацией приложение показывает, какие данные и правила расчёта попадут в BI».

## Какую роль действительно играет ИИ

В текущей первой версии BitrixGPT не получает право выполнять произвольные действия с CRM. Он помогает перевести человеческий запрос в понятный рецепт поддержанного сценария.

Сервер повторно проверяет его ответ. Он сверяет название шаблона, список полей, типы колонок, период и фильтры. Если запрос выходит за пределы поддержанной логики, интерфейс сообщает, что нужна доработка.

Такой подход даёт две практические вещи. Пользователь общается с системой естественным языком. Команда сохраняет контроль над тем, какие расчёты допускаются и какие данные уходят в BI.

Сегодня ИИ поддерживает один проверенный шаблон с новыми сделками. В будущем каталог можно расширять: добавить конверсию, когорты, показатели из 1С или другие варианты. Каждый новый шаблон сначала нужно описать, проверить на примерах и включить в серверные правила.

> **Место для скриншота 4.** Успешный ответ BitrixGPT и подпись о серверной проверке рецепта.
>
> Подпись: «ИИ предлагает рецепт, а сервер проверяет допустимость каждого поля и правила расчёта».

## Что происходит после публикации

После публикации BI-конструктор знает схему таблицы: её название, колонки и их типы. Когда ему нужны актуальные строки, он обращается к отдельному adapter-сервису.

**Adapter** — небольшой сервер-переводчик между BI-конструктором и нашей расчётной логикой. Он отвечает на четыре вида запросов:

1. Подтверждает, что сервис доступен.
2. Возвращает список таблиц.
3. Описывает колонки выбранной таблицы.
4. Выдаёт строки данных.

При запросе строк adapter получает сделки из CRM, применяет правила рецепта, группирует результаты по неделям и менеджерам, затем возвращает готовую таблицу. Битрикс24 показал эти реальные строки в нативном интерфейсе. Этим мы подтвердили всю цепочку от CRM до BI-таблицы на живом портале.

> **Место для скриншота 5.** Нативная таблица Битрикс24 с реальными строками по менеджерам и неделям.
>
> Подпись: «BI-конструктор получил реальные агрегированные данные через adapter».

## Почему adapter должен быть доступен по HTTPS

**HTTPS** — защищённый способ открыть адрес в интернете. В этой задаче он нужен потому, что за данными обращается сервер Битрикс24. Браузер аналитика в этот момент может быть закрыт.

Временный Cloudflare Tunnel позволил проверить работу на локальном компьютере. Такой адрес исчезает после остановки туннеля или компьютера, поэтому он подходит для эксперимента.

Для постоянной работы мы используем отдельный VibeCode-сервер `living-bi-dataset-adapter`. У него есть постоянный HTTPS-поддомен. В публичный доступ открывается только этот технический adapter, основной интерфейс дашборда остаётся закрытым для внешних запросов.

VibeCode различает прямой доступ к серверу и политику доступа HTTPS-приложения. Для BI-коннектора важен публичный HTTPS-поддомен, который возвращает JSON — структурированный ответ с данными. Прямой IP-адрес и SSH для работы датасета не требуются.

> **Место для скриншота 6.** Настройка отдельного VibeCode-приложения или успешный ответ `/health`.
>
> Подпись: «Отдельный технический сервис получает постоянный HTTPS-адрес для запросов BI-конструктора».

## Как мы защищаем портал и данные

Публикация датасета относится к внешним действиям, поэтому в интерфейсе есть несколько предохранителей.

- Сначала показывается preview будущей схемы.
- Публикация требует вручную ввести `publish_dataset`.
- Удаление требует отдельную фразу `delete_dataset` и работает только с нашими датасетами `vibecode_ai_*`.

Для доступа к API используется OAuth. **OAuth** — механизм, при котором Битрикс24 выдаёт приложению ограниченное разрешение работать от имени установленного приложения. Секреты и токены не попадают в браузер. Adapter хранит их на сервере в зашифрованном виде и умеет обновлять краткоживущий доступ.

В интерфейсе также есть статус синхронизации: он показывает последнее успешное обращение BI-конструктора к adapter-у. Строки CRM и токены в этот статус не попадают.

> **Место для скриншота 7.** Блок публикации, поле `publish_dataset` и статус синхронизации.
>
> Подпись: «Внешние действия требуют явного подтверждения, а синхронизация отображается отдельно».

## Ограничения, которые стоит назвать прямо

Нативный график аналитик собирает вручную. Это разовая работа для каждого нового датасета. После сохранения график продолжает получать новые строки от adapter-а.

Первая версия поддерживает ограниченный набор расчётов. Расширение каталога возможно, когда команда описывает бизнес-правило, добавляет его в серверный валидатор и проверяет результат на данных портала.

Битрикс24 также задаёт технические правила для имён и типов:

- Имя датасета начинается с буквы, использует строчные латинские буквы, цифры и подчёркивания.
- Имя поля начинается с заглавной латинской буквы и имеет ограниченную длину.
- Поддерживаются целые числа, строки, дробные числа, дата и дата со временем.

Входящего вебхука для этой задачи недостаточно. Вебхук — простой адрес для вызова API. Методы BI-коннектора требуют OAuth-контекст локального приложения Битрикс24.

## Что уже доказано и что дальше

На реальном интеграционном портале мы уже подтвердили главную технологическую цепочку: CRM-данные рассчитываются в adapter-е и появляются в нативной BI-таблице. В приложении работают preview, BitrixGPT-планировщик, серверная проверка рецепта, безопасная публикация, мониторинг синхронизации и управляемое удаление.

Сейчас завершается перенос adapter-а на постоянный VibeCode HTTPS-адрес. После успешной проверки мы переключим четыре технических callback-адреса существующего BI-коннектора и ещё раз откроем нативную таблицу. Тогда набор продолжит обновляться без временного туннеля на локальном компьютере.

Главный результат этой работы уже можно сформулировать так:

> API нативного BI Битрикс24 позволяет строить управляемый путь от текстового бизнес-запроса до обновляемого расчётного набора данных. ИИ упрощает подготовку и проверку этого набора, а аналитик сохраняет контроль над визуальной частью отчёта.
