# PRD: «Живой BI-дашборд» — приложение для Битрикс24 с ИИ-редактором отчётов на платформе Вайбкод

**Версия:** 0.1 (черновик)
**Дата:** 07.08.2026
**Статус:** на обсуждении

Проект включает два связанных результата:
1. **Приложение** — встраиваемый в Битрикс24 дашборд на данных портала, который пользователь редактирует в чате с ИИ-моделью (BitrixGPT через API Вайбкод).
2. **Статья** — публикация, где приложение служит сквозным демо: от идеи и ограничений нативного BI до работающего сценария «изменил отчёт словами».

---

## 1. Проблема

BI-конструктор Битрикс24 — мощный инструмент, но настройка отчётов под себя требует компетенций аналитика: датасеты, вычисляемые поля, метрики, фильтры. Руководителю, которому нужно «покажи конверсию только по новым клиентам и убери тестовую воронку», приходится либо разбираться самому, либо идти к аналитику/интегратору.

При этом ИИ-агент Битрикс24 не может помочь с BI-отчётами, и причина не в «слабости» агента:

- **Первичная причина: у BI-конструктора нет REST API для отчётов.** Дашборды, графики и метрики нативного BI редактируются только вручную через UI. Единственная группа методов с «BI» в названии — `biconnector.*` (коннекторы/источники/датасеты) — предназначена для подключения *внешних* источников данных в «Рабочее место аналитика», а не для управления отчётами. Шаблоны отчётов для Маркетплейса экспортируются архивом из интерфейса, тоже без REST.
- **Вторичная причина:** агент работает через фиксированный набор инструментов, и BI-конструктор в них не входит — а добавить такой инструмент не на чем (см. выше).

**Вывод, на котором строится продукт:** редактируемый ИИ отчёт нельзя сделать *внутри* нативного BI — его нужно построить *рядом*, на тех же данных портала, средствами платформы Вайбкод.

## 2. Целевая аудитория

| Сегмент | Потребность |
|---|---|
| Руководитель отдела продаж / собственник малого-среднего бизнеса | Смотреть ключевые метрики и менять отчёт под вопрос дня без аналитика |
| Администратор портала / «продвинутый пользователь» | Быстро собирать дашборды под запросы руководства |
| Партнёр/интегратор Битрикс24 (аудитория статьи) | Понять паттерн «приложение + встроенный ИИ» на Вайбкоде и переиспользовать его |

## 3. Терминология

- **BI-конструктор** — нативный инструмент аналитики Битрикс24 («Рабочее место аналитика»): датасеты, дашборды, метрики, вычисляемые поля, фильтры.
- **ИИ-агент Битрикс24** — встроенный агент/CoPilot портала, работающий через фиксированный набор инструментов.
- **Вайбкод** — платформа Битрикс24 для разработки приложений с AI-агентами: собственное API (`/v1/...`), серверы Black Hole, встроенные AI-модели, бот-платформа, AI-поиск.
- **BitrixGPT** — собственные модели Битрикс24 (`bitrixgpt-*`), доступные в Вайбкоде бесплатно через OpenAI-совместимый API.
- **Дашборд (в этом PRD)** — наше приложение: набор виджетов, описанный декларативной JSON-спекой, отрисованный на фронтенде и наполненный данными через aggregate API Вайбкода. **Не** нативный BI-отчёт.

## 4. Позиционирование и честные ограничения (для продукта и статьи)

1. Мы **не редактируем нативные BI-отчёты** — это невозможно через API. Мы строим отдельный дашборд на тех же данных портала.
2. Мы **не читаем конфигурацию нативных отчётов** — «перенести отчёт из BI-конструктора» в MVP нельзя, можно воспроизвести аналог по описанию.
3. Формулировка про приватность: «данные не передаются сторонним LLM-провайдерам — BitrixGPT работает в инфраструктуре Битрикс24». Не писать «данные не покидают портал»: они обрабатываются в контуре Вайбкод/Black Hole, и это описывается честно (скоупы, ключи, туннель).
4. Это не замена полноценному BI: агрегация Вайбкода считает числовые функции по выборке до 5000 записей; для больших объёмов и сложных срезов остаётся нативный BI-конструктор.

## 5. Скоуп MVP

### Функции

- **F1. Рендер дашборда из JSON-спеки.** Типы виджетов: KPI-карточка, bar (верт./гориз.), line, pie/donut, таблица. Общий фильтр периода на дашборд + переопределение на виджете.
- **F2. Данные из портала.** Сущности MVP: сделки, задачи, компании, звонки (по наличию в entity API); стадии воронок через `/v1/statuses`. Все запросы — только чтение (list/aggregate/fields).
- **F3. Чат-редактор с ИИ.** Панель чата рядом с дашбордом. Модель (BitrixGPT, `/v1/ai/chat/completions`, function calling) меняет спеку через инструменты, а не генерирует её свободным текстом.
- **F4. Версионирование и undo.** Каждое применённое изменение — новая версия спеки; кнопка «откатить»; diff «что изменил ИИ» в ответе чата.
- **F5. Доступы.** Вход через авторизацию Битрикс24 (ключ `vibe_app_...`, OAuth); дашборд видят авторизованные пользователи портала; редактирование — владелец (в MVP).
- **F6. Seed-скрипт тестовых данных** (нужен и для разработки, и для п. 5 статьи): компании, сделки по стадиям с датами за 6–12 мес., задачи с дедлайнами/просрочкой. Через `/v1/{entity}/batch` (до 500 записей/запрос).

### Вне скоупа (non-goals MVP)

- Запись/изменение данных CRM и задач (приложение read-only по данным портала).
- Редактирование или чтение нативных BI-отчётов (невозможно технически).
- Экспорт нашего дашборда в шаблон BI-конструктора для Маркетплейса (ручной путь существует, но вне MVP; упомянуть как перспективу).
- Несколько дашбордов, шаринг наружу портала, алерты/рассылки — кандидаты на v2.

## 6. Архитектура

```
Битрикс24 (iframe-встройка)
   │
   ▼
Frontend (SPA: рендер дашборда + чат)          ← без ключей, только сессия
   │  HTTPS
   ▼
Backend (BFF) на Black Hole                     ← здесь живёт ключ vibe_app_...
   ├── /api/dashboard  (CRUD спеки, версии)     → SQLite/Postgres на Black Hole
   ├── /api/data       (прокси-агрегации + кэш) → Вайбкод /v1/{entity}/aggregate, /v1/statuses
   └── /api/chat       (диалог с ИИ + tools)    → Вайбкод /v1/ai/chat/completions (bitrixgpt)
```

Ключевые решения:

- **BFF-паттерн обязателен.** Ключ Вайбкода хранится только на сервере Black Hole; фронтенд ключей не видит. Авторизация пользователей — через OAuth приложения (`vibe_app_...`), каждый работает в рамках своих прав.
- **Кэш агрегаций** на BFF (TTL ~5 мин, ручное обновление кнопкой) — из-за лимитов: 60 запросов/мин на ключ, 10 rps на портал, авто-пагинация Вайбкода при `limit > 50`.
- **Встройка.** Справочник placements Вайбкода динамический — на старте проверить `GET /v1/placements/available`. Целевой вариант — пункт в меню BI-аналитики (`BI_ANALYTICS_MENU`), но у него особенность: handler открывается GET-запросом **без** `AUTH_ID`/`member_id`, авторизацию придётся вести самим (своя сессия). Запасной вариант MVP — обычная встройка в меню/страница приложения, где контекст приходит штатно.

## 7. Модель данных: спека дашборда

```jsonc
{
  "version": 7,
  "title": "Продажи: обзор",
  "period": { "field": "closedate", "preset": "this_quarter" },
  "widgets": [
    {
      "id": "w1",
      "type": "bar",
      "title": "Сумма выигранных сделок по менеджерам",
      "entity": "deals",
      "filter": { "stageSemanticId": "S" },
      "groupBy": ["assignedById"],
      "aggregate": { "fn": "sum", "field": "opportunity" },
      "options": { "horizontal": true, "sort": "desc", "limit": 10, "color": "#2fc6f6" }
    },
    {
      "id": "w2",
      "type": "kpi",
      "title": "Конверсия в успех",
      "entity": "deals",
      "computed": { "expr": "won / total", "format": "percent" }
    }
  ]
}
```

- Спека валидируется схемой (zod/JSON Schema): whitelist сущностей, полей (из `/v1/{entity}/fields`), функций агрегации, типов виджетов.
- `computed` — ограниченный набор выражений над результатами агрегаций виджета (без произвольного кода).
- Версии хранятся полностью (append-only) → дешёвый undo и аудит изменений ИИ.

## 8. Дизайн ИИ-редактора

**Модель:** `bitrixgpt-5.5` (fallback: `model: "auto"`). Function calling — подтверждён документацией; JSON mode проверить на практике (см. открытые вопросы).

**Инструменты (tools), доступные модели:**

| Tool | Назначение |
|---|---|
| `get_dashboard()` | Текущая спека + версия |
| `list_entities()` / `get_entity_fields(entity)` | Метаданные: какие сущности и поля доступны |
| `preview_aggregate(query)` | Пробный запрос агрегации — проверить, что срез возвращает данные, до применения |
| `apply_changes(patch[])` | JSON-patch к спеке; сервер валидирует схему и создаёт новую версию |
| `revert(version)` | Откат |

**Guardrails:**

- Модель меняет **только спеку** — у неё нет инструментов записи в CRM/задачи и нет произвольных запросов к API.
- Минимизация данных: в контекст модели попадают метаданные полей и **агрегированные** результаты (`preview_aggregate`), а не карточки клиентов. Имена/телефоны/суммы конкретных сделок в промпт не передаются.
- Любой `apply_changes` проходит серверную валидацию; невалидный патч возвращается модели с ошибкой на исправление (retry-петля, максимум N попыток).
- В ответе пользователю чат показывает человекочитаемый diff: «изменил тип графика w1 на горизонтальный, добавил фильтр “исключая воронку Тест”».

**Системный промпт (тезисно):** роль «редактор дашборда», описание схемы спеки, правило «сначала preview, потом apply», запрет придумывать поля — только из `get_entity_fields`, стиль коротких подтверждений.

## 9. Безопасность

| Аспект | Решение |
|---|---|
| Скоупы Битрикс24 | Минимум: `crm`, `task`+`tasks`, `user`, `placement`. Не запрашивать лишнего — это же тезис статьи |
| Скоупы Вайбкод | `vibe:ai` (автоматический), `vibe:infra` (деплой), опц. `vibe:storage` |
| Ключи | `vibe_app_...` только на сервере (BFF); в репозитории/фронтенде/статье ключей нет; в скриншотах статьи — замазаны |
| Доступ к приложению | Настройки доступа Black Hole: авторизованные пользователи портала; редактор — владелец |
| Приватность ИИ | BitrixGPT в инфраструктуре Битрикс24, без сторонних LLM-провайдеров; данные обрабатываются в контуре Вайбкод/Black Hole (описать в статье честно) |
| Данные в промптах | Только агрегаты и метаданные; лог запросов к ИИ — проверка на отсутствие сырых ПДн |

## 10. Риски и открытые вопросы

| # | Риск/вопрос | План |
|---|---|---|
| 1 | Есть ли `BI_ANALYTICS_MENU` в справочнике placements Вайбкода | Проверить `GET /v1/placements/available` на старте M2; fallback — встройка в меню |
| 2 | `BI_ANALYTICS_MENU` не передаёт auth-контекст | Своя сессия на BFF; если дорого — остаёмся на обычной встройке в MVP |

| 5 | Лимиты 60 req/min (ключ) и 10 rps (портал) | Кэш агрегаций, батчинг запросов виджетов, debounce обновлений |
| 6 | Формулировка про приватность BitrixGPT | Согласовать точную фразу с продуктовой командой до публикации статьи |
| 7 | Терминология «ИИ-агент Битрикс24» vs CoPilot vs OpenClaw | Свериться с актуальным неймингом на момент публикации |

## 11. Метрики успеха

**Приложение (демо-качество):**
- Сценарий «изменение отчёта фразой» проходит end-to-end < 30 сек (правка) / < 15 сек round-trip ИИ.

- Все три демо-сценария (6.1–6.3) воспроизводимы читателем по тексту с нуля (ключ → промпт → результат).

## 13. План статьи (переработанный)

Рабочий заголовок: **«BI-отчёты, которые можно менять словами: строим дашборд с ИИ-редактором на платформе Вайбкод»**

1. **Что такое BI-конструктор и BI-отчёты в Битрикс24.** Коротко: датасеты, дашборды, метрики; кому и зачем.
2. **Зачем бизнесу настраивать отчёты под себя — и почему это сложно вручную.** Боль: настройка требует компетенций аналитика; типовые «хотелки» руководителя.
3. **Что умеет ИИ-агент Битрикс24 и почему он не редактирует BI-отчёты.** Две причины в правильном порядке: (а) у BI-конструктора нет REST API для отчётов — `biconnector.*` только про внешние источники данных; (б) у агента фиксированный набор инструментов, и расширить его в сторону BI не на чем. Мостик: значит, редактируемый ИИ отчёт строим *рядом*, на тех же данных.
4. **Чем поможет Вайбкод.** Отдельное приложение-дашборд внутри портала; entity API + aggregate; встроенные AI-модели (BitrixGPT, function calling); серверы Black Hole; безопасность: минимальные скоупы, ключ на сервере, модель в инфраструктуре Битрикс24 — данные не уходят сторонним LLM-провайдерам.
5. **Готовим тестовые данные.** Тем же агентом: промпт → seed-скрипт через batch API. Мета-момент «платформа демонстрирует сама себя».
6. **Создаём дашборд и правим его через ИИ.**
   - 6.1 *Визуально:* «сделай график по менеджерам горизонтальным и в цветах бренда, KPI-карточки подними наверх».
   - 6.2 *Логику:* «конверсию считай только по новым клиентам, исключи воронку “Тест”, период — текущий квартал».
   - 6.3 *Новый бизнес-запрос:* «добавь виджет: просроченные задачи по отделам и динамика просрочки по неделям».
   Каждый сценарий: фраза → diff от ИИ → результат на экране (+undo как отдельный кадр).
7. **Итог.** Что получил пользователь; ограничения подхода (5000 записей, лимиты, когда нужен настоящий BI); безопасность ещё раз в одном абзаце; CTA — ключ Вайбкода, ссылка на документацию и готовый промпт для повторения.

## Приложение А. Подтверждённые факты из документации

- BI-конструктор: методы REST только `biconnector.*` (connector/source/dataset) — интеграция внешних источников в «Рабочее место аналитика»; работают только в контексте приложения; API управления дашбордами отсутствует. Шаблоны отчётов для Маркетплейса — экспорт архива из UI, без REST.
- Виджет `BI_ANALYTICS_MENU` (scope `placement`): пункт в меню BI-аналитики; handler открывается GET-запросом без `AUTH_ID`/`member_id`/`PLACEMENT_OPTIONS`; `OPTIONS` не сохраняются.
- Вайбкод entity API: `/v1/{entity}` + `/search`, `/aggregate` (count/sum/avg/min/max, groupBy до 5 полей, числовые функции — до 5000 записей), `/batch` (до 500), `/fields`; лимит 5000 на выдачу, авто-пагинация при limit > 50; 10 rps на портал; 60 req/min на ключ (по умолчанию).
- Вайбкод AI: `/v1/ai/chat/completions`, OpenAI-совместимый, streaming, function calling, `model: "auto"`; бесплатные модели: BitrixGPT 5.5 / 5.5 Thinking / 5.5 Agent, GPT-OSS 120B, Gemma 4 26B (+Thinking); BYOK для сторонних провайдеров.
- Вайбкод placements: `GET /v1/placements/available`, `POST /v1/placements/bind|unbind`, `GET /v1/placements`; нужен ключ `vibe_app_...` и скоуп `placement`; справочник динамический.
- Ключи: `vibe_api_...` (личный, как вебхук) и `vibe_app_...` (OAuth-приложение); Black Hole — серверы без публичного IP, доступ через туннель, гибкие права просмотра; оплата в Vibes.
- Скоупы: Битрикс24 (`crm`, `task`+`tasks`, `user`, `placement`, `biconnector`, ...) + `vibe:*` (`vibe:ai`, `vibe:infra`, `vibe:storage`, `vibe:search`, `vibe:feedback`).
