# Сценарий подтверждения работы второй версии продукта

## Цель

Подтвердить в портале `b24-w9apyi.bitrix24.ru`, что пользователь описывает расчётный набор данных словами, получает проверенную схему, публикует её в BI-конструктор и видит строки, которые отдаёт адаптер.

Это и есть практическая демонстрация второй статьи.

## Что уже подготовлено

- В портале доступно приложение «AI-редактор BI-отчётов».
- В приложении есть блок **AI Dataset Publisher · Этап 3**.
- Для портала развёрнут отдельный публичный адаптер. Его HTTPS-адрес доступен, OAuth-настройка сохранена, автосон отключён.
- Поддержан один безопасный рецепт: новые сделки по менеджерам, неделям и валютам за текущий квартал с исключением повторных сделок и воронки «Тест».

Сейчас в исходных данных пять подходящих сделок, которые собираются в три строки. Этого достаточно, чтобы подтвердить техническую цепочку. Для наглядного графика позднее стоит добавить больше тестовых сделок.

## Шаг 1. Открыть приложение

1. В левом меню портала выберите **AI-редактор BI-отчётов**.
2. Прокрутите страницу до блока **AI Dataset Publisher · Этап 3**.

Ожидаемый результат: видно поле «Опишите, какие данные нужны» и кнопку «Подготовить с BitrixGPT».

> [Скриншот 1: открытый блок AI Dataset Publisher]

## Шаг 2. Подготовить рецепт

Вставьте в поле этот запрос:

> Новые сделки по менеджерам по неделям за текущий квартал без повторных сделок и воронки «Тест»

Нажмите **«Подготовить с BitrixGPT»**.

Ожидаемый результат:

- статус «Preview готов»;
- название набора `vibecode_ai_deal_intake_weekly`;
- объяснение источника, периода, фильтров и расчёта;
- схема из восьми полей;
- сообщение, что сервер проверил рецепт по разрешённому шаблону.

Это шаг подготовки: датасет в Битрикс24 ещё не создаётся.

> [Скриншот 2: preview рецепта и схема полей]

## Шаг 3. Проверить схему и подтвердить черновик

Убедитесь, что в схеме есть поля:

| Поле | Смысл |
| --- | --- |
| `WEEK_START` | начало недели |
| `MANAGER_ID` | идентификатор менеджера |
| `MANAGER_NAME` | менеджер |
| `CURRENCY_ID` | валюта |
| `NEW_DEALS` | число новых сделок |
| `PIPELINE_AMOUNT` | сумма сделок |
| `AVERAGE_AMOUNT` | средняя сумма |
| `WEEKLY_SHARE_PERCENT` | доля недельного потока, % |

Нажмите **«Подтвердить черновик»**.

Ожидаемый результат: появляется сообщение, что черновик подтверждён внутри приложения. Внешних изменений в портале на этом шаге ещё нет.

> [Скриншот 3: подтверждённый черновик]

## Шаг 4. Опубликовать набор в BI-конструктор

Ниже черновика найдите блок **«Публикация в BI-конструктор»**. В поле подтверждения введите ровно:

```text
publish_dataset
```

Нажмите **«Опубликовать в BI-конструктор»**.

Это единственный шаг, который создаёт или обновляет объект в портале. Он затрагивает только технические объекты с префиксом `vibecode_ai_`: коннектор, источник и датасет `vibecode_ai_deal_intake_weekly`. CRM-записи, существующие отчёты и чужие датасеты не меняются.

Ожидаемый результат: приложение сообщает об успешной публикации и показывает сведения о созданном датасете.

> [Скриншот 4: успешная публикация]

## Шаг 5. Проверить синхронизацию

После успешной публикации в том же блоке становится доступна кнопка **«Проверить синхронизацию»**. До публикации она может отсутствовать или быть бесполезной: проверять ещё нечего.

Нажмите её.

Ожидаемый результат: сообщение, что адаптер доступен, и время последней успешной синхронизации.

> [Скриншот 5: успешная синхронизация]

## Шаг 6. Убедиться, что BI получает строки

Откройте в Битрикс24 раздел BI-конструктора с таблицами. Найдите таблицу или датасет `vibecode_ai_deal_intake_weekly` и откройте предпросмотр.

Ожидаемый результат: видны колонки из схемы и строки с неделей, менеджером, валютой и числом сделок. Три строки при текущих тестовых данных — нормальный результат.

> [Скриншот 6: таблица с данными из адаптера]

## Шаг 7. Собрать один нативный график

В BI-конструкторе создайте отчёт вручную на основе этого датасета:

1. Выберите измерение `WEEK_START`.
2. Добавьте разбиение по `MANAGER_NAME`.
3. Используйте метрику `SUM(NEW_DEALS)`.
4. Сохраните график или таблицу на дашборд.

Ожидаемый результат: нативный BI-отчёт строится по строкам, которые запрашивает у адаптера Битрикс24. После создания этот график можно оставлять на дашборде: при следующем обновлении данных адаптер отдаст актуальные строки.

> [Скриншот 7: нативный график по опубликованному датасету]

## Критерий готовности второй версии

Сценарий подтверждён, если пройдены все пункты:

1. Текстовый запрос превратился в preview со схемой.
2. Черновик подтверждён.
3. Датасет опубликован в BI-конструктор.
4. Синхронизация успешна.
5. В BI видны строки датасета.
6. Аналитик собрал хотя бы один нативный график.

## Текущее ограничение демо

Поле запроса пока понимает только указанный безопасный рецепт. Для нового типа выгрузки сначала добавляют рецепт на сервере: разрешённые поля, фильтры и правила расчёта. После этого ИИ сможет готовить схему и для нового сценария.
