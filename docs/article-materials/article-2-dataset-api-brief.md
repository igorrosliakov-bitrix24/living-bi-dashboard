# Задание на вторую статью: ИИ готовит наборы данных

Ниже сохранено исходное задание разработчика.

## Что строить дальше: ИИ готовит наборы данных

### Идея простыми словами

Сейчас в нативном BI аналитик делает две работы: собирает данные (какие поля взять, как посчитать, откуда достать) и собирает отчёт (какой график, какие фильтры, как разложить на дашборде).

API Битрикс24 позволяет автоматизировать первую половину. Значит ИИ может взять её на себя: пользователь описывает словами, какой набор данных ему нужен, ИИ его формирует и публикует в «Рабочее место аналитика». Дальше аналитик один раз собирает по нему график — и всё, набор живёт и обновляется сам.

Получается разделение труда: ИИ делает подготовку данных, человек — наглядную часть. Обещание остаётся честным: ИИ не заявлен как инструмент, который самостоятельно рисует график.

### Почему это работает, а редактирование отчёта — нет

Через REST доступны наборы данных: их можно создавать, обновлять, менять состав полей. Конфигурация самого отчёта — тип графика, метрика, вычисляемое поле, фильтр и раскладка — через REST не отдаётся. Поэтому ИИ может готовить данные для отчёта, а график аналитик собирает в BI-конструкторе.

### Что имеет смысл публиковать, а что нет

Самая важная часть — публиковать данные с дополнительной ценностью. Сделки, лиды и звонки уже представлены во встроенных наборах данных Битрикс24.

Подходящие варианты:

- расчётные показатели: конверсия по менеджерам по неделям с исключением тестовой воронки, скорость прохождения стадий, когорты клиентов по месяцу первой сделки;
- внешние данные: заказы из 1С, производственные показатели, сведения из ERP;
- сведённые наборы, где данные портала соединены с внешними источниками.

Ценность появляется, когда в BI передаётся результат расчёта или объединения, который встроенный BI сам не формирует.

### Как это выглядит для пользователя

Пользователь пишет в нашем дашборде: «нужен набор данных — конверсия по менеджерам по неделям, без тестовой воронки».

ИИ формирует описание набора: как он называется, какие в нём колонки и какого они типа. Наш сервер проверяет описание по правилам платформы и создаёт набор через REST. Битрикс24 приходит к адаптеру за строками. Адаптер считает их по данным портала и отдаёт. Аналитик один раз собирает по этому набору график в BI-конструкторе. Дальше набор обновляется, а состав полей ИИ может поменять по новому запросу.

### Что для этого нужно сделать

- Адаптер с четырьмя точками входа: проверка доступности, список таблиц, описание полей таблицы, выдача данных. Он уже написан — осталось довести и выложить.
- Публичный адрес по HTTPS для адаптера. Битрикс24 сам к нему обращается, поэтому сервер должен быть доступен извне.
- Локальное приложение Битрикс24 с OAuth и правом `biconnector`. Это обязательное условие: методы работают только в контексте приложения.
- Инструменты для ИИ: создать набор данных и обновить состав его полей, с проверкой на стороне сервера перед применением.
- Кнопки в интерфейсе: опубликовать набор, обновить данные, посмотреть время последней синхронизации, удалить.

### Ограничения, о которых надо сказать сразу

- График для каждого нового набора один раз собирает аналитик.
- Имя набора данных начинается с буквы, использует строчные латинские буквы, цифры и подчёркивание; длина — до 230 символов.
- Имена полей начинаются с заглавной латинской буквы; длина — до 32 символов.
- Поддерживаемые типы полей: целое число, строка, дробное число, дата, дата со временем.
- Вебхука недостаточно: нужно приложение с OAuth.
